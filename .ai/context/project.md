# Project context

TraceDump AI is an AI-assisted waste-dumping detection and investigation project. Its intended flow is: a Python worker monitors XProtect sources, applies motion and object detection, requests Hafnia analysis against recording references, extracts useful evidence, and persists suspected incidents to Supabase. A Next.js application will let investigators review those records and evidence.

The worker in `video-analytics/` provides XProtect discovery/acquisition/export, activity detection, Hafnia analysis, evidence extraction, simulation-run deduplication, and Supabase persistence through a durable local outbox. Next.js implements authentication, operations mapping, incident investigation, review history, and reports. A separate playback worker prepares private browser-compatible recordings. Live integrations depend on separately installed SDKs, credentials, model weights, and services. AI-positive results remain suspected incidents requiring human review.

## Issue 2: playback recovery changes (2026-10-23)

- The player renews five-minute access URLs before expiry, restores position and playing state after metadata loads, and waits for metadata before an initial event jump.
- A network/source error gets one automatic access refresh. Decode errors and repeated failures display a retry action instead of claiming expiry. Explicit retry first requests access, then requests preparation only when the server reports a recording state requiring it. Transport/signing failures do not cause preparation requests.
- Each successful access response reloads the video element even when a signer returns the same URL. This permits retry without assuming a new token string.
- The API reports signing failure as failed (503), retaining expired (410) for a known retention deadline.
- Migration `20261023190000_requeue_expired_incident_recordings.sql` allows an available but overdue row to be requeued without waiting for cleanup. It preserves the existing operator authorization and does not interrupt pending/preparing rows. The migration has not been applied to any live database.
- Local real-video browser verification: `.runtime/verification/playback-recovery-browser.mjs`, using the Croydon MP4 with mocked access/preparation boundaries. Checks metadata-safe initial seek, renewal at a 12-second position, decode-error messaging, and manual retry. This is not an authenticated live-app test.
- Local SQL verification: `.runtime/verification/playback-requeue-sql.mjs`, using PGlite and explicitly synthetic minimal tables/auth/hash fixtures. Checks function syntax, initial requests, unexpired/overdue available rows, active preparation, and authorization denial. Full Supabase schema/Storage integration remains unverified.
- Human UI check: open an existing incident, refresh playback, play and seek, leave it open past the five-minute access lifetime, and confirm playback/position remain usable. Distinguish unavailable original footage from access renewal. Test retention re-preparation in an authorized database after applying the migration before declaring that path verified.
